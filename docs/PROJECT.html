Static SPA that calculates VRAM requirements, latency estimates, and total cost of ownership for running LLMs locally. Compare NVIDIA GPUs, DGX systems, and Apple Silicon side by side.

04. Math formulas

VRAM — Simple mode

total_GB = params × bytesPerParam × 1.2 Flat 20% overhead. Good for "will this fit at all?" — ignores context length.

VRAM — Detailed mode

weights_GB = params × bytesPerParam n_layers = max(32, round(√params × 8)) ← estimated (wrong for MoE/GQA) d_model = max(2048, round(√params × 600)) ← estimated kv_cache_GB = (2 × n_layers × d_model × context × batch × 2) / 1e9 overhead_GB = weights × 0.1 + 1 total_GB = weights + kv_cache + overhead KV stays FP16 (2 bytes) even when weights are INT4. n_layers/d_model estimates are ±30% for modern dense models, worse for MoE.

Prefill (TTFT) ±30-50% optimistic

flops = 2 × active_params × 1e9 × prompt_tokens ttft_ms = flops / (tflops_fp16 × 1e12 × 0.3) × 1000 efficiency=0.3 (conservative). For MoE, active_params = routed experts only. Multi-GPU: tflops × n^0.85 scaling.

Decode (tokens/sec) ±25%

read_GB = active_params × bytesPerParam ← MoE reads only active experts efficiency = 0.7 (dense) | 0.2 (MoE) ← MoE has routing + scattered access overhead ms_per_token = read_GB / (bandwidth_gbs × efficiency) × 1000 tok_per_sec = 1000 / ms_per_token Memory-bandwidth-bound. Calibrated: Qwen 3.5 35B-A3B Q4 on M4 mini ≈ 35 tok/s · H100 Llama 70B FP16 ≈ 30 tok/s.

TCO

yearly_kWh = (power_W / 1000) × 24 × 30 × months × 0.5 elec_cost = yearly_kWh × rate_per_kWh tco = hw_price × count + elec_cost 0.5 = 50% utilization assumption. Does NOT include cooling, networking, server chassis, or amortization.

Multi-GPU scaling

TypeScale exponentExampleNotes
NVIDIA tensor parallel^0.852× GPUs ≈ 1.8× speedNVLink/PCIe; ~10% VRAM overhead per extra GPU
Apple cluster (EXO)^0.552× nodes ≈ 1.4× speedThunderbolt 4 (~40 Gbps) vs NVLink (~7,200 Gbps)
DGX internaln/aAlready baked inDGX entries use units field; can't be further stacked

Known formula weaknesses

IssueImpactFix
KV cache estimated from √paramsHigh — wrong for MoE/GQAFetch config.json from HuggingFace (see EXTENDING.md)
INT8/FP8 TFLOPS not usedMedium — underestimates H100/B200 prefillAdd tflops_int8 field, use when quant=fp8/int8
GQA not modelledMedium — overestimates KV cache for Llama3, Qwen3Add nKvHeads to model, scale KV by nKvHeads/nHeads
Prefill efficiency=0.3 flatLow — short prompts are bandwidth-bound, not computeSwitch to bandwidth model below 512 tokens

09. Dev commands

Run locally

cd repo
npm install
npm run dev        # http://localhost:5173

Production build

npm run build      # → dist/
npm run preview    # serve dist/ locally

Deploy (Vercel)

git push origin main
# Vercel auto-deploys on push
# ~30s rebuild time

Common pitfalls

# Grid columns must sum to 12
# Don't fetch inside useMemo
# CORS blocks retailer sites (browser)
# React keys: use hw.id / m.id, not index
